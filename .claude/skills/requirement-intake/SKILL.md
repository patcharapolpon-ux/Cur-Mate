# Requirement Intake

Skill นี้รับ requirement ดิบจากผู้ใช้ ทำให้ชัดเจนผ่านการถามตอบ แล้วมอบหมายให้ sub agent `requirement-writer` เขียนเอกสารจริงลงใน vault ตาม `CLAUDE.md`

## ขั้นตอน

### 1. รับ requirement ดิบ

ใช้ข้อความ requirement ที่ผู้ใช้ส่งมาพร้อมกับ skill นี้ (args) หรือข้อความล่าสุดในบทสนทนาถ้าไม่มี args แนบมา

### 2. สำรวจเอกสารที่เกี่ยวข้องก่อนตัดสินใจ

- อ่าน `docs/01-requirements/backlog.md` (ถ้ามี) และไล่ดูไฟล์ใน `docs/01-requirements/01-spec/*.md` (ยกเว้น `index.md`) เพื่อหาเอกสารที่อาจซ้ำซ้อนหรือเกี่ยวข้องกับ requirement นี้
- ถ้าผู้ใช้อ้างอิงถึงเอกสาร requirement เดิมโดยตรง (พูดถึงชื่อ/หัวข้อ/ไฟล์) ให้เปิดอ่านเอกสารนั้นเต็มๆ แล้ววิเคราะห์ว่าอยู่ในกรณีใด:
  1. **ชี้แจง/เพิ่มเติมเล็กน้อยในสโคปเดิม** → ตัดสินใจ "แก้ไขเอกสารเดิม"
  2. **ความต้องการใหม่ที่ขยายสโคป/เปลี่ยนทิศทางจนเอกสารเดิมล้าสมัย** → ตัดสินใจ "สร้างเอกสารใหม่ + ย้ายเอกสารเดิมไป archived"
  3. **ไม่แน่ใจว่าเข้าเคสไหน** → ต้องถามผู้ใช้ (รวมเป็นหนึ่งในคำถามชี้แจงข้อ 3)
- ถ้าไม่มีเอกสารเดิมเกี่ยวข้อง ให้ตัดสินใจเป็น "สร้างเอกสารใหม่" ตามปกติ

### 3. ถามคำถามชี้แจงจุดที่ไม่แน่ใจ

สำหรับทุกจุดของ requirement ที่ยังกำกวมหรือขาดข้อมูล (เช่น ขอบเขต, ผู้ใช้เป้าหมาย, edge case, priority, ควรสร้างเอกสารใหม่หรือแก้ไขเอกสารเดิม) ให้ใช้ `AskUserQuestion`

**กฎสำคัญ: ทุกคำถามที่ถามต้องมีตัวเลือกแนะนำอย่างน้อย 3 แนวทางเสมอ** พร้อมคำอธิบายสั้นๆ ของแต่ละตัวเลือกว่าหมายถึงอะไร/ผลต่างกันอย่างไร (ผู้ใช้ยังเลือก "Other" เพิ่มเองได้เสมออยู่แล้ว)

ถามเป็นชุดๆ จนกว่าจะมีข้อมูลพอเขียน spec ที่สมบูรณ์ ไม่จำเป็นต้องถามทุกอย่างในครั้งเดียวถ้ามันขึ้นอยู่กับคำตอบก่อนหน้า

### 4. มอบหมายให้ sub agent เขียนเอกสารจริง

เมื่อ requirement ชัดเจนพอแล้ว ให้เรียก Agent tool โดยระบุ `subagent_type: "requirement-writer"` และส่ง context ให้ครบในคำสั่ง (prompt) ได้แก่:

- วันที่ปัจจุบันในรูปแบบ `YYYYMMDD` (แปลงจาก currentDate ที่มีอยู่ใน context)
- สรุป requirement ที่ชัดเจนแล้วทั้งหมด (รวมคำตอบจากคำถามในข้อ 3)
- หัวข้อสั้นๆ สำหรับตั้งชื่อไฟล์ (แนะนำ slug ภาษาอังกฤษ)
- การตัดสินใจจากข้อ 2 ("สร้างใหม่" หรือ "แก้ไขเอกสารเดิม + path ของเอกสารเดิม") พร้อมเหตุผลสั้นๆ

**อย่าเขียนไฟล์เอกสารเองใน skill นี้** — ให้ sub agent เป็นผู้เขียน/แก้ไขไฟล์ spec, อัปเดต `backlog.md`, และเพิ่มบันทึกใน `docs/05-log/{YYYYMMDD}-log.md` ทั้งหมด เพื่อให้การจัดรูปแบบเอกสารสอดคล้องกันทุกครั้ง

### 5. รายงานผลกลับผู้ใช้

สรุปให้ผู้ใช้ทราบแบบกระชับ พร้อมลิงก์ไฟล์ (markdown link relative path) ไปยัง:
- เอกสาร spec ที่สร้าง/แก้ไข
- `docs/01-requirements/backlog.md`
- ไฟล์ log ของวันนี้

## ข้อควรจำ

- เนื้อหาเอกสารทั้งหมดต้องเป็นภาษาไทย ตาม `CLAUDE.md`
- ห้ามลบเอกสารเดิม ให้ย้ายไป `docs/00-archived/` เท่านั้น
- การอ้างอิงข้ามเอกสารในไฟล์ `.md` ของ vault ใช้ Obsidian wikilink แบบ relative path เสมอ
