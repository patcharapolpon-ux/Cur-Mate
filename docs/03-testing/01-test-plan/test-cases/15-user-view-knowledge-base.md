## สมมติฐาน / ข้อจำกัดของต้นแบบที่ใช้ในการออกแบบ Test Case นี้

- ฟีเจอร์นี้ยังไม่มี journey หรือหน้าจอต้นแบบ (prototype mockup) แยกเป็นของตัวเอง ตามที่ระบุไว้ตรงกันทั้งใน `feature-list.md` (ฟีเจอร์ 15) และ `acceptance-criteria.md` (หมายเหตุท้าย AC-15-01) — test case ทั้ง 4 ข้อด้านบนจึงออกแบบขั้นตอนทดสอบและชื่อช่องทางเข้าถึง (เช่น "ดูรายการเอกสาร/กฎเกณฑ์" ที่ chip ในหน้าเลือกชุดเกณฑ์, ปุ่ม/แถบ "ดูขอบเขต/รายการเอกสารของชุดเกณฑ์ที่เลือกไว้" ระหว่างสนทนากับแชทบอท) โดยอิงจากคำอธิบายในเอกสารต้นทางที่ระบุไว้ตรงๆ เท่านั้น ไม่เดารายละเอียดภาพ/ตำแหน่งปุ่มที่ยังไม่มีอยู่จริง เมื่อมีการออกแบบ mockup โดยละเอียดของมุมมองนี้ในเวอร์ชันถัดไป ควรกลับมาปรับปรุงชื่อหน้าจอ/element ใน test case นี้ให้ตรงกับหน้าจอจริง
- ชื่อเอกสาร/กฎเกณฑ์ที่ใช้เป็น Test Data ในไฟล์นี้ (เช่น "ประกาศกระทรวงการอุดมศึกษาฯ เรื่อง เกณฑ์มาตรฐานหลักสูตรระดับปริญญาตรี พ.ศ. 2565", "ภาคผนวก ก มาตรฐานผลการเรียนรู้ระดับปริญญาตรี", "เกณฑ์คุณวุฒิระดับปริญญาตรี สาขาวิศวกรรมคอมพิวเตอร์ พ.ศ. 2565", กฎเกณฑ์ pending/rejected ข้อ ก./ข.) เป็นข้อมูลสมมติที่คิดขึ้นให้สอดคล้องกับรูปแบบชื่อที่ใช้อยู่แล้วใน [[../../../03-testing/01-test-plan/test-cases/06-manage-criteria-knowledge-base|test-cases/06-manage-criteria-knowledge-base]] และ [[../../../03-testing/01-test-plan/test-cases/07-review-approve-criteria-rules|test-cases/07-review-approve-criteria-rules]] เนื่องจากชุดเกณฑ์ "เกณฑ์มาตรฐานหลักสูตร ป.ตรี 2565" และ "เกณฑ์คุณวุฒิ วิศวกรรมคอมพิวเตอร์ 2565" ที่ใช้อ้างอิงซ้ำในหลายไฟล์ยังไม่เคยมีการระบุรายชื่อเอกสาร/กฎเกณฑ์แบบละเอียดไว้ที่ใดมาก่อน
- TC-15-003 อาศัยการนำขั้นตอนของ TC-07-006 (อัปโหลดเอกสารเพิ่มเข้าชุด active) และ TC-07-007 (ปฏิเสธกฎเกณฑ์) มาต่อกันเป็น pre-condition composite เพื่อจำลองสถานการณ์ที่ AC-15-02 ต้องการ (กฎเกณฑ์ 3 สถานะปะปนกันในชุดเดียว) เนื่องจากยังไม่มี test case ใดที่ทดสอบสถานการณ์ผสมนี้โดยตรงมาก่อน — สอดคล้องกับหมายเหตุในหัวข้อสมมติฐานของ TC-07-006 ที่ระบุว่ายังไม่มีหน้าจอต้นแบบแสดงสถานะผสมโดยตรงเช่นกัน
