## สมมติฐาน / ข้อจำกัดของต้นแบบที่ใช้ในการออกแบบ Test Case นี้

- **TC-07-002**: หน้าต้นแบบ `07-rule-review-approval.html` แสดงข้อความกฎเกณฑ์เป็น `<p class="rule-text">` แบบอ่านอย่างเดียว ยังไม่มีช่อง inline-edit ที่ทำงานได้จริงสำหรับให้แอดมินแก้ไขข้อความกฎเกณฑ์ก่อนอนุมัติ (มีเพียงปุ่ม "อนุมัติ (Approve)" และ "ปฏิเสธ (Reject)") ขั้นตอน "แก้ไข" ใน AC-07-02 จึงถูกทดสอบเฉพาะในเชิงตรวจสอบเนื้อหาก่อนกดอนุมัติเท่านั้น ตามที่ต้นแบบปัจจุบันรองรับจริง — หากมีการเพิ่มช่อง inline-edit ในต้นแบบเวอร์ชันถัดไป ควรกลับมาเพิ่ม step การแก้ไขข้อความจริงในไฟล์นี้
- **TC-07-006**: ยังไม่มีหน้าจอต้นแบบที่แสดงสถานะผสม (กฎเกณฑ์อนุมัติแล้วเดิม + กฎเกณฑ์ใหม่ pending) ของชุดเกณฑ์เดียวกันหลังอัปโหลดเอกสารเพิ่มเข้าชุดที่ active อยู่แล้วโดยตรง (ทั้ง `06-create-criteria-set.html` และ `07-rule-review-approval.html` เป็น mockup ของ flow สร้างชุดใหม่/ตรวจสอบชุดที่เพิ่งสร้างเท่านั้น) ขั้นตอนทดสอบและผลลัพธ์ที่คาดหวังของ TC-07-006 จึงอ้างอิงจากพฤติกรรมที่ระบุไว้ตรงๆ ใน [[../../../01-requirements/01-spec/20260823-02-criteria-knowledge-base|criteria-knowledge-base]] FR ข้อ 4 (หัวข้อ "กรณีอัปโหลดเอกสารเพิ่มเข้าชุดเกณฑ์ที่ active อยู่แล้ว") เป็นหลัก — เมื่อมีการออกแบบหน้าจอเฉพาะสำหรับกรณีนี้ในต้นแบบเวอร์ชันถัดไป ควรกลับมาปรับปรุงรายละเอียด UI ของ test case นี้ให้ตรงกับหน้าจอจริง
- (ล้าสมัย — แก้ไขแล้ว 2026-09-12) เดิมบันทึกไว้ว่า "ปุ่ม 'ปฏิเสธ (Reject)' ในต้นแบบเป็นเพียงตัวอย่างต้นแบบที่แสดง alert แจ้งว่ายังไม่ได้กำหนดพฤติกรรม ... จึงยังไม่มี test case สำหรับการปฏิเสธกฎเกณฑ์ในไฟล์นี้" — ปัจจุบัน spec ต้นทาง ([[../../../01-requirements/01-spec/20260823-02-criteria-knowledge-base|criteria-knowledge-base]] FR ข้อ 7-9) และต้นแบบ `07-rule-review-approval.html` ได้รับการอัปเดตให้รองรับพฤติกรรมปฏิเสธ/พิจารณาใหม่/ลบรายข้อ/ลบทั้งชุด/นำกลับไป pending แล้ว จึงเพิ่ม TC-07-007 ถึง TC-07-013 ครอบคลุม AC-07-07 ถึง AC-07-12 ไว้ด้านบน
- **TC-07-007 / TC-07-008 / TC-07-010**: หน้าต้นแบบทั้งหมดในชุดนี้เป็น mock ฝั่งหน้าจอ (frontend only) เท่านั้น ยังไม่มีการเชื่อมต่อกับฐานข้อมูล/backend จริง ดังนั้นพฤติกรรม "บันทึกประวัติการเปลี่ยนสถานะ (audit trail)" ตาม AC-07-07/AC-07-08 และ "ลบแบบ cascade ไม่เหลือข้อมูลค้างอ้างอิง" ตาม AC-07-10 จึงทดสอบได้เฉพาะผลลัพธ์ที่มองเห็นได้บนหน้าจอ (สถานะ/รายการที่เปลี่ยนไป) เท่านั้นในรอบนี้ ต้องกลับมาเพิ่ม test case ระดับข้อมูล/API เมื่อมี tech design และ backend จริงใน [[../../../02-design/02-technical/index|02-technical]]
