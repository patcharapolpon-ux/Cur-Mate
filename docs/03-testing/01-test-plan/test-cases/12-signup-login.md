## สมมติฐาน / ข้อจำกัดของต้นแบบที่ใช้ในการออกแบบ Test Case นี้

- **TC-12-002**: หน้าต้นแบบ `10-login.html` ปัจจุบัน redirect ไปยัง `05-criteria-dashboard.html` เสมอหลังเข้าสู่ระบบสำเร็จ ไม่ได้แยกปลายทางตามบทบาทจริง (ตามหมายเหตุใน dev-note ของไฟล์ต้นแบบเอง) จึงทดสอบได้เฉพาะพฤติกรรม "ยืนยันตัวตนสำเร็จแล้ว redirect ออกจากหน้า login" ในรอบนี้ ส่วนการแยกปลายทางตามบทบาทจริง (แอดมิน/ผู้ใช้งานทั่วไป/ผู้บริหาร ไปคนละหน้า) ต้องกลับมาเพิ่ม test case ทดสอบซ้ำเมื่อมี backend/role-based routing จริงใน [[../../../02-design/02-technical/index|02-technical]]
- **TC-12-004**: ฟอร์มสมัครสมาชิกในต้นแบบ (`11-signup.html`) ใช้ `<form novalidate>` และสคริปต์ฝั่ง client ตรวจสอบเฉพาะว่าฟิลด์ถูกกรอกครบหรือไม่ (truthy check) ยังไม่มีการตรวจสอบรูปแบบอีเมล (เช่น ต้องมีเครื่องหมาย @) แยกต่างหากจากกรณีเว้นว่าง ขั้นตอน/ผลลัพธ์ที่คาดหวังของ TC-12-004 จึงอ้างอิงพฤติกรรมที่ AC-12-04 กำหนดไว้ตรงๆ เป็นหลัก (validation ทั่วไปเท่านั้น ไม่เดากฎเชิงตัวเลข/รูปแบบเฉพาะ) เมื่อต้นแบบหรือ backend เพิ่มการตรวจสอบรูปแบบอีเมลจริง ควรกลับมาปรับปรุงขั้นตอนทดสอบนี้ให้ตรงกับข้อความ/พฤติกรรมจริงบนหน้าจอ
- **TC-12-006**: ยังไม่มีปุ่ม/เมนู "ออกจากระบบ (logout)" ปรากฏอยู่ในหน้าต้นแบบชุดปัจจุบันของ [[../../../02-design/01-prototypes/20260823-prototype-v1/index|20260823-prototype-v1]] (สำรวจแล้วไม่พบ) ขั้นตอนทดสอบนี้จึงออกแบบอ้างอิงจาก [[../../../02-design/01-prototypes/20260912-06-user-journey-signup-login|user journey ผู้ใช้สมัครสมาชิกและเข้าสู่ระบบ]] ขั้นตอนที่ 11 และ AC-12-05 โดยตรง เมื่อมีการเพิ่มหน้าจอ/ปุ่ม logout จริงในต้นแบบเวอร์ชันถัดไป ควรกลับมาปรับปรุงรายละเอียด UI ของ test case นี้ให้ตรงกับหน้าจอจริง
