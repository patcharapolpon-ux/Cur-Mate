# ACL.md — Access Control List (การบ้าน Module 2 v2)

ตารางสิทธิ์ของแต่ละบทบาท (role) ในระบบ — เพิ่มเมื่อ 2026-09-07 พร้อมระบบ login จริง (ดู [SCOPE.md](./SCOPE.md) หัวข้อ "ระบบ login" และ [CLAUDE.md](./CLAUDE.md))

ค่า `role` เก็บใน Firestore field `users/{uid}.role` เป็นโค้ดภาษาอังกฤษ (ไม่ใช่ข้อความไทยเหมือนตอนแรกที่ทำ) มี 2 ค่าที่ระบบรู้จัก: `ADMIN` และ `STAFF`

## ตารางสิทธิ์

| บทบาท (Role) | ทำได้ (Allowed) | ทำไม่ได้ (Not allowed) |
| --- | --- | --- |
| **ADMIN** | จัดการชุดเกณฑ์ในระบบทั้งหมด — สร้างชุดเกณฑ์ใหม่ (หน้า `06-create-criteria-set.html`), ตรวจสอบ/อนุมัติ/ไม่อนุมัติกฎเกณฑ์ย่อย, เปิดใช้งาน/แก้ไขชุดเกณฑ์อีกครั้ง, ลบชุดเกณฑ์และกฎเกณฑ์ย่อย (หน้า `05-criteria-dashboard.html`, `07-rule-review-approval.html`); จัดการบทบาทของผู้ใช้ **คนอื่น** ในระบบ (หน้า `manage-users.html`) | เปลี่ยนบทบาทของ**ตัวเอง** (บังคับด้วย UI — แถวของตัวเองในหน้า `manage-users.html` แก้ไม่ได้) |
| **STAFF** | อ่านชุดเกณฑ์/กฎเกณฑ์ที่ **เปิดใช้งานแล้ว (active)** เพื่อศึกษา (หน้า `05`/`07` โหมดอ่านอย่างเดียว — ไม่เห็นชุดที่ยัง pending); นำหลักสูตรเข้าเพื่อตรวจสอบความสอดคล้อง¹, เลือกใช้ชุดเกณฑ์ที่มีอยู่แล้วในระบบ (เฉพาะสถานะ "เปิดใช้งาน")¹ | จัดการชุดเกณฑ์ในระบบ (สร้าง/แก้ไข/อนุมัติ/ลบ — หน้า `06` เข้าไม่ได้เลย, ปุ่มจัดการทั้งหมดในหน้า `05`/`07` ถูกซ่อน); จัดการบทบาทของผู้ใช้คนใด (หน้า `manage-users.html` เข้าไม่ได้เลย) รวมถึงของตัวเอง |

¹ **หมายเหตุสำคัญ — ยังไม่ implement**: ฟีเจอร์ "นำหลักสูตรเข้าเพื่อตรวจสอบความสอดคล้อง" และ "เลือกใช้ชุดเกณฑ์" ยังไม่มีอยู่จริงในโค้ดของการบ้านนี้ (เป็นฟีเจอร์ "ตรวจสอบความสอดคล้อง มคอ.2" ตามสเปกโปรเจกต์หลัก `docs/01-requirements/01-spec/20260812-01-tqf2-consistency-check.md` ซึ่งเป็นคนละฟีเจอร์กับ "จัดการฐานความรู้เกณฑ์" ที่การบ้าน v2 นี้ทำอยู่) ตารางนี้บันทึกไว้เป็นสิทธิ์ที่ตั้งใจให้มีตามที่ผู้ใช้ระบบระบุไว้ ส่วนที่ implement จริงในโค้ดตอนนี้สำหรับ STAFF มีแค่ "อ่านเพื่อศึกษา" เท่านั้น

## การบังคับใช้สิทธิ์ในโค้ด (ปัจจุบัน)

- บังคับผ่าน **UI เท่านั้น** (`js/auth.js` + role-aware rendering ในแต่ละหน้า) — ยังไม่มี Firestore Security Rules รองรับ (โปรเจกต์ยังเป็น open test rules) ถ้ายิง Firestore API ตรงๆ ข้ามหน้าเว็บไป สิทธิ์เหล่านี้จะไม่ถูกบังคับใช้จริง
- หน้า `06-create-criteria-set.html` และ `manage-users.html` เป็น ADMIN ล้วน — เข้าด้วย role อื่นจะเจอ "ไม่มีสิทธิ์เข้าถึง" ทันที (ปิดกั้นด้วย `window.CURMATE_REQUIRE_ADMIN` ใน `js/auth.js`)
- หน้า `05-criteria-dashboard.html` และ `07-rule-review-approval.html` เปิดให้ทั้งสอง role เข้าดูได้ — ปุ่ม/ข้อมูลที่เป็นสิทธิ์จัดการของ ADMIN (สร้าง/ลบ/อนุมัติ/เปิดใช้งาน) ถูกซ่อนสำหรับ STAFF และ STAFF เห็นเฉพาะชุดเกณฑ์สถานะ `active` เท่านั้น
- บัญชีใหม่ทุกบัญชีจากหน้า `signup.html` ได้ role `STAFF` เสมอ (ไม่ให้เลือกเองแล้ว) — ADMIN คนแรกของระบบต้องตั้งค่าด้วยมือผ่าน Firebase Console (ผู้ใช้ระบบจัดการเอง ไม่ได้ทำอัตโนมัติในโค้ด) ADMIN คนถัดไปเลื่อนบทบาทให้กันเองผ่านหน้า `manage-users.html`
