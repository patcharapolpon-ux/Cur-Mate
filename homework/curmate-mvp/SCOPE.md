# SCOPE.md — ขอบเขตโครงงานสำหรับการบ้าน Module 2 (สัปดาห์ที่ 6-9)

โครงงาน: **Curmate** — ระบบตรวจสอบความสอดคล้องของเอกสารรายละเอียดหลักสูตร (มคอ.2)

ส่วนที่เลือกมาทำ (จาก spec ที่มีอยู่แล้วใน `docs/01-requirements/01-spec/20260823-02-criteria-knowledge-base.md`):
**"การจัดการฐานความรู้เกณฑ์มาตรฐานหลักสูตร"** — แอดมินอัปโหลดเอกสารเกณฑ์ → AI สกัดเป็น "กฎเกณฑ์" ทีละข้อ → แอดมินตรวจสอบและอนุมัติทีละข้อ (หรือ bulk approve) → เมื่อกฎเกณฑ์ทุกข้อในชุดได้รับการอนุมัติ ชุดเกณฑ์เปลี่ยนสถานะเป็น "เปิดใช้งาน (active)"

## ประโยคเดียวสรุปขอบเขต

> ระบบของฉันเก็บ **กฎเกณฑ์มาตรฐานหลักสูตร (rules)** ที่ **แอดมิน** สร้างขึ้นจากการอัปโหลดเอกสารเกณฑ์ แต่ละข้อเลือก **ชุดเกณฑ์ (criteria set)** ได้ และมีสถานะ **รอตรวจสอบ (pending)** → **อนุมัติแล้ว (approved)** โดย **แอดมิน** เป็นคนกดเปลี่ยน

## ตารางขอบเขต

| | ของ Curmate |
|---|---|
| 📁 โฟลเดอร์หลัก | `rules` |
| 📁 โฟลเดอร์ประเภท | `criteriaSets` |
| 📁 โฟลเดอร์ย่อย | `reviewLog` |
| ✏️ ช่องบอกว่าเป็นของใคร | `uploadedBy` · `uploadedByName` |
| 🔀 สถานะทั้งหมด | รอตรวจสอบ (pending) · อนุมัติแล้ว (approved) |
| 👤 คนที่สร้างรายการ | แอดมิน (ผู้อัปโหลดเอกสารเกณฑ์) |
| 👤 คนที่เปลี่ยนสถานะ | แอดมิน (ผู้อนุมัติกฎเกณฑ์) |
| 📝 ช่องข้อความยาวที่ AI จะอ่าน | `ruleText` (ข้อความกฎเกณฑ์ที่ AI สกัดจากเอกสาร) |
| 🤖 งานที่ AI ช่วย (สัปดาห์ที่ 8) | (แนวคิด) อ่าน `ruleText` แล้วช่วยแนะนำว่าควรอยู่ชุดเกณฑ์ไหน หรือซ้ำกับกฎที่มีอยู่แล้วหรือไม่ |

## หมายเหตุ

- **role ที่ใช้งานจริงในสโคปนี้มีตัวเดียวคือ "แอดมิน"** ทำทั้งสองฝั่ง (อัปโหลดเอกสาร → เกิด `rules` ใหม่ / อนุมัติ `rules` → เปลี่ยนสถานะ) ส่วน role "เจ้าหน้าที่/อาจารย์ผู้จัดทำหลักสูตร" (ผู้ที่จะอัปโหลด มคอ.2 เข้ามาตรวจสอบเอง) อยู่ใน spec คนละไฟล์ (`20260812-01-tqf2-consistency-check.md`) — **ไม่ได้อยู่ในสโคปการบ้านรอบนี้**
- สถานะของ `rules` มีแค่ 2 ค่า (pending/approved) ไม่มี "ปฏิเสธ (rejected)" เพราะ spec ต้นทางระบุไว้ตรงๆ ว่ายังไม่ได้กำหนดพฤติกรรมของการปฏิเสธ (ดู `docs/03-testing/01-test-plan/test-cases/07-review-approve-criteria-rules.md` หัวข้อสมมติฐาน)
- สถานะของ `criteriaSets` (pending/active) เป็นค่าที่**ขึ้นกับกฎเกณฑ์ทั้งหมดในชุดว่าอนุมัติครบหรือยัง** — ในเวอร์ชัน MVP นี้ยังตั้งค่าตรงๆ ตอน seed ข้อมูล ไม่ได้คำนวณอัตโนมัติจากโค้ด

## ขอบเขตที่ยังไม่ทำ (เก็บไว้ Backlog Sprint 2)

- การอัปโหลดเอกสาร PDF/Word จริงและการสกัดกฎเกณฑ์ด้วย AI จริง (ตอนนี้ข้อมูลกฎเกณฑ์เป็นข้อมูลตัวอย่างที่ seed ไว้ล่วงหน้า)
- ปุ่ม "ปฏิเสธ (Reject)" กฎเกณฑ์ (พฤติกรรมยังไม่ถูกกำหนดใน spec ต้นทาง)
- การคำนวณสถานะ `criteriaSets` อัตโนมัติจากสถานะของ `rules` ทั้งหมดในชุด
- ฟีเจอร์อัปโหลด มคอ.2 เพื่อตรวจสอบความสอดคล้อง (คนละ spec — `20260812-01-tqf2-consistency-check.md`)
